# 04 Naive-Diversity Threshold Sensitivity

Purpose: support Supplementary Table S15 and the S15 threshold-sensitivity analysis of the inference-stage naive-diversity threshold.

Implementation scripts:

- `code/experiments/04_naive_diversity_threshold_sensitivity/run_inference_only_threshold_sensitivity.py`: reruns inference on fixed graph-construction outputs while changing only the inference-stage `min_naive` threshold.
- `code/experiments/00_benchmark_utils/summarize_eval_results.py` and `code/experiments/04_naive_diversity_threshold_sensitivity/build_threshold_sensitivity_sources.py`: summarize generated evaluation CSVs into the S15 source CSVs.
- `code/experiments/04_naive_diversity_threshold_sensitivity/summarize_threshold_sensitivity_s15.mjs`: writes compact CSV/Markdown summaries of the threshold-sensitivity result values used for Supplementary Table S15.

Scope: this analysis keeps the graph fixed and varies only the inference-stage naive-diversity threshold. It is separate from analyses that change both graph construction and inference filtering.

Key parameters: `min_naive` thresholds `0`, `1`, `2`, and `3`; simulation-specific inference settings `penalty_K=0` and `pi_min=0.1` were used for this in silico stress analysis.

Inputs: fixed Scenario A graph and validation folders generated by `experiments/01_in_silico_trbv_benchmarks/simu_validation_pipeline.sh`, defaulting to `experiments/01_in_silico_trbv_benchmarks/results`. Use `RESULTS_ROOT` when pointing the analysis to another relative rerun directory.

## Run

After experiment 01 has generated Scenario A graph, label, mutation, inference,
and validation folders, run:

```bash
bash experiments/04_naive_diversity_threshold_sensitivity/run_rebuild.sh
```

Use `RESULTS_ROOT` to point to a separate experiment 01 rerun:

```bash
RESULTS_ROOT=experiments/01_in_silico_trbv_benchmarks/results \
  bash experiments/04_naive_diversity_threshold_sensitivity/run_rebuild.sh
```

## Outputs And Downstream Use

Rerun summaries are written under `generated/summary` and `generated/report`.
The report step writes compact CSV/Markdown files rather than recreating the
formal workbook layout.
